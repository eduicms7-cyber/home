# 윈도우 컴퓨터 설정 (홈페이지 작업일지 자동 반영)

맥에는 2026-10-25에 설정을 마쳤다. 윈도우에서는 아래 순서대로 한 번만 하면 된다.

## 1. home 폴더 내려받기

다른 프로젝트(ent-tool, naru 등)가 들어 있는 폴더에서 PowerShell을 열고 실행한다. home이 다른 프로젝트 **옆**에 있어야 규칙이 쉽게 찾는다.

```
git clone https://github.com/eduicms7-cyber/home.git
```

이미 home 폴더가 있으면 그 안에서 `git pull`만 한다.

## 2. 전역 규칙 파일에 규칙 넣기

파일 위치: `C:\Users\<사용자이름>\.claude\CLAUDE.md`

가장 쉬운 방법은 윈도우의 Claude Code에서 home 폴더를 열고 이렇게 말하는 것이다.

> docs/윈도우_설정.md의 "넣을 규칙"을 내 전역 CLAUDE.md의 작업일지 규칙 바로 아래에 넣어 줘

## 3. 확인

home 폴더에서 실행해 "최신 상태입니다"가 나오면 끝이다.

```
node scripts/sync-logs.mjs
```

Node.js나 `gh`가 없다고 나오면 ent-tool의 `docs/새컴퓨터_준비.md` 설치 순서를 따른다.

---

## 넣을 규칙

```markdown
## 홈페이지(home)에도 작업일지 반영
다른 프로젝트에서 작업일지를 쓰면 개인 홈페이지(GitHub `eduicms7-cyber/home`)의 `projects.js`에도 반영한다. 맥·윈도우 두 컴퓨터에서 같은 파일을 고치므로 순서를 지킨다.
1. 이 컴퓨터의 home 폴더를 찾는다(보통 작업 중인 프로젝트 옆의 `../home`). 없으면 사용자에게 알리고 넘어간다.
2. 고치기 전에 home에서 `git pull`로 최신본을 받는다.
3. 그 프로젝트 항목의 `logs` 맨 앞에 `{ date: "YYYY.MM.DD", title, description }`을 추가한다. 같은 날짜가 이미 있으면 그 항목을 고친다. 방문자가 읽는 글이므로 키·계정·경로·커밋 해시 같은 내부 사정은 빼고 한두 문장으로 쓴다.
4. home에서 커밋하고 바로 push한다.
- 홈페이지에 카드가 아직 없는 프로젝트는 마음대로 추가하지 말고 카드를 만들지 사용자에게 묻는다.
- home 저장소에서 하는 작업 자체는 이 규칙의 대상이 아니다.
- 빠진 기록 점검: home 폴더에서 `node scripts/sync-logs.mjs` (GitHub의 각 프로젝트 작업일지와 비교해 홈페이지에 없는 날짜를 보여 준다).
```
